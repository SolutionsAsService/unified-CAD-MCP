# Install and audit report (2026-10-12)

Host: Linux/WSL2 x86_64, Python 3.12.3, no sudo, no ensurepip. Starting revision
606749f. This audit covers the integration code, configuration, bootstrap, tests and
docs; upstream backend source was read where behavior mattered but not re-audited
line by line.

## Install result

- python3 -m venv --without-pip .venv, then pip from get-pip.py, then
  pip install -c locks/unified-py312.txt -e '.[dev]' (FastMCP 4.1.0, MCP 2.3.0).
- scripts/bootstrap_backends.py installed all four pinned backends into .backends/.
- Real stdio handshake (protocol 2025-11-25) and tools/list: **73 tools default**
  (1 + 18 kicad + 33 cad + 19 pcb + 2 freecad), **103 with both experimental gates**
  (pcb 35, freecad 16), **8 resources**. This matches the README.
- Source drift check (fetch_audit_sources.py + audit_sources.py --check): no drift
  (18/33/35/16 tools; 202/45/178/54 inventory entries).
- Native runtimes: kicad-cli/pcbnew are **not available** (not on conda-forge; no
  sudo for distro packages), so every kicad_* native operation (DRC, export, autoroute,
  panelize) and every pcb_* live IPC call remain unverified; pcb_* returns the upstream
  "Not connected" JSON. FreeCAD 26.3 **was installed** without sudo from conda-forge via
  micromamba into a user prefix; the cad_* FreeCAD path (STEP inspection, entity paging,
  box revision, SVG preview) then worked end to end through unified stdio, after the
  workaround in finding 3. No FreeCAD GUI or NiRuLink addon ran, so freecad_* still
  only reaches "listener unavailable".

## Findings

| # | Severity | Finding | Disposition |
|---|---|---|---|
| 1 | Medium (security default) | The bootstrap wrote the freecad backend **enabled** in generated configs, exposing freecad_execute_python (unrestricted code execution in the GUI user session) by default, while docs implied the optional backend stays disabled. Exploitation needs the user to install and run the NiRuLink addon, but the default was looser than documented. | **Fixed:** generated freecad entry is "enabled": false unless --enable-freecad or --backend freecad; tests updated; README/freecad.md updated. |
| 2 | Low (correctness / flaky test) | The per-backend timeout_seconds also bounds the MCP initialize request, so the effective startup deadline is min(timeout_seconds, init_timeout_seconds). The protocol test used a 2 s timeout and failed reproducibly on this host (about 4 s interpreter + FastMCP startup). | **Fixed in test** (8 s request deadline, 30 s operation); behavior documented in README. Production default (120 s) unaffected. |
| 3 | High for native use (upstream) | design-mcp-server's freecad_worker.py imports json and math before FreeCAD. With conda-forge FreeCAD 26.3, import FreeCAD removes those names from the __main__ globals, so every cad_* FreeCAD operation failed with NameError. | **Upstream fix needed** in SolutionsAsService/design-mcp-server (import stdlib after FreeCAD, or inside functions). Not patched here (backends are not edited). Operator workaround: a DESIGN_MCP_FREECAD_PYTHON shim named python that pre-imports FreeCAD and runs the worker with runpy (see verification.md). conda installs also need a .pth adding the env's lib/ directory so import FreeCAD works under python -I. |
| 4 | Medium (licensing) | This integration repository has no LICENSE file, and design-mcp-server still declares none. | Documented in README; owner decision required. Not invented here. |
| 5 | Info (isolation) | Each backend is a separate subprocess and venv, launched without a shell, with an explicit minimal environment. This is process separation, not an OS sandbox. | Confirmed; already documented. |
| 6 | Info (network) | Unified is stdio-only and opens no listener. The NiRuLink addon listens on localhost:9876 without authentication (upstream); the adapter refuses non-loopback hosts and connects numerically. kicad_* may contact LCSC (after accept_tos) and run FreeRouting/Java. | Confirmed; documented. |
| 7 | Info (paths) | cad_* enforces its asset/revision/preview roots (parent-escape rejection verified). kicad_* and pcb_* accept any path the user can access; freecad export paths are any absolute path on the GUI host. drone_* touches no files. | Confirmed; documented as "project root is not a sandbox". |
| 8 | Info (arbitrary Python) | freecad_execute_python is one of the two default tools whenever the freecad backend is enabled; the 14 helpers need UNIFIED_FREECAD_EXPERIMENTAL=1; helper string arguments reject quotes, backslashes and control characters to stop interpolation injection; imported upstream files are SHA-256 verified. | Confirmed opt-in at backend level (now also by bootstrap default, see 1). |
| 9 | Low (supply chain) | Backends are pinned to exact Git commits, but dependency locks are version constraints without hashes; CI actions are pinned to tags, not SHAs; get-pip.py is fetched unpinned. | Recommendation: pip --require-hashes locks, SHA-pinned actions. Not changed. |
| 10 | Low (test gaps) | No test exercises the non-dry-run bootstrap output (needs network); no native KiCad test; no NiRuLink GUI test; the published example config was not validated against the schema. | Added test_example_configuration_matches_schema and tests/test_drone.py; native/GUI gaps remain. |
| 11 | Low (doc drift) | README assumed ensurepip; counts did not cover disabled backends; init-timeout semantics were undocumented; README said "example config disables" FreeCAD while generated configs enabled it. | Fixed in README, freecad.md and coverage.md. |
