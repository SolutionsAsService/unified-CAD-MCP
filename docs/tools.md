# Tool list

Generated by `scripts/list_tools.py`; do not edit by hand. Which tools a running server
advertises depends on the operator config (backends, `drone_tools`, `airframe`) and on backend gates
(see [coverage.md](coverage.md)). Call `unified_get_context` for the live routing and backend state.

## airframe_*

- `airframe_aero_crosscheck`: Independent aerodynamic cross-check with AeroSandbox (MIT): level-flight trim, AeroBuildup (NeuralFoil + fuselage) and VLM neutral point, static margin, CL/CD, Cn_beta, Cl_beta.
- `airframe_build_fixed_wing`: Build a parametric fixed-wing airframe headlessly in FreeCAD and validate it.
- `airframe_flotation_check`: HEURISTIC static hydrostatics for floating or amphibious vehicles (e.g. a waterproof multirotor that lands on water).
- `airframe_inspect_step`: Deterministic STEP validation: per-solid validity, closed shells, volume (mesh-integrated AND OCCT GProp), area, centroid, bounding box; optional mass/inertia for a uniform density.
- `airframe_render_preview`: Headless PNG previews (matplotlib Agg, orthographic, flat shading) of a build's viewer JSON, written to <build>/previews/.
- `airframe_vspaero_analysis`: Third independent aero check with OpenVSP/VSPAERO (NASA): rebuild wing, V-tail and fuselage in OpenVSP, run a VSPAERO alpha sweep (VLM or thick-surface panel) and OpenVSP Parasite Drag build-up.

## cad_*

- `cad_add_project_evidence`: Create a new project revision with user-attested evidence linked to snapshot references.
- `cad_add_project_parameter`: Append a source-linked scalar configuration parameter in a new project revision.
- `cad_add_project_requirement`: Append a source-linked, unvalidated scalar requirement as a new project revision.
- `cad_compare_box_revisions`: Compare dimensions of two hash-checked box revisions without editing either.
- `cad_convert_quantity`: Convert a finite scalar between explicit compatible units; no claim verification.
- `cad_create_assembly_manifest`: Record a bounded candidate hierarchy and user positions, with no fit claims.
- `cad_create_box_revision`: Opt-in: save a new, parametric FreeCAD box to the separate revision root; never edit inputs.
- `cad_create_project_record`: Create an immutable generic project record from a CURRENT snapshot.
- `cad_create_project_snapshot`: Record a bounded, hash-linked set of generic assets and CAD revisions.
- `cad_get_freecad_entities`: Page bounded STEP/FCStd BREP entity measurements (not a manufacturing validation).
- `cad_get_scope`: Describe implemented capabilities and write opt-in boundary.
- `cad_get_stl_entities`: Return a bounded page of STL triangle faces, unique edges, or unique vertices.
- `cad_inspect_assembly_manifest`: Recheck candidate links; absent component envelopes always imply UNKNOWN fit.
- `cad_inspect_asset`: Hash an asset and run limited container checks; no dimensions or fit analysis.
- `cad_inspect_cad_envelopes`: Check bounded FCStd object AABBs; missing/overlapping envelopes remain UNKNOWN.
- `cad_inspect_cad_preview`: Verify preview/source hashes; visual interpretation remains a separate review step.
- `cad_inspect_cad_revision`: Hash-check and inspect a saved revision from the dedicated output root.
- `cad_inspect_component_candidate`: Verify candidate record hash, not dimensions, pad mapping or part compatibility.
- `cad_inspect_freecad_model`: Inspect STEP geometry or an FCStd feature tree through FreeCAD's bundled Python.
- `cad_inspect_project_record`: Check project, parent and snapshot hashes; mark directly impacted evidence links.
- `cad_inspect_project_snapshot`: Recheck snapshot references; CURRENT means only that file hashes still match.
- `cad_inspect_stl_geometry`: Calculate topology and geometric metrics for a triangulated STL mesh.
- `cad_list_assembly_manifests`: Page bounded assembly hierarchies; hashes are not physical-fit validation.
- `cad_list_assets`: List file metadata beneath the configured read-only root.
- `cad_list_cad_revisions`: Page hash-verified CAD revision summaries; flag missing or altered artifacts.
- `cad_list_component_candidates`: Page recorded candidate identifiers and unverified footprint links.
- `cad_list_project_records`: Page hash-checked immutable project records, not engineering approvals.
- `cad_list_project_snapshots`: Page bounded snapshot summaries with manifest integrity statuses.
- `cad_measure_freecad_distance`: Measure the nearest separation between two named FCStd shapes, without modifying the document.
- `cad_preview_cad_revision`: Export bounded, CAD-derived SVG wireframe into a dedicated scratch root.
- `cad_register_component_candidate`: Store caller-forwarded pcbparts/KiCad observations; pairing remains UNVERIFIED.
- `cad_revise_box_parameters`: Save a new parameterized box revision without overwriting its hash-checked parent.
- `cad_rollback_box_revision`: Make a new box child with dimensions from a hash-verified ancestor; preserve both inputs.

## drone_*

- `drone_fixed_wing_analysis`: HEURISTIC fixed-wing UAV analysis: planform, tail volumes (V-tail via Purser-Campbell), neutral point and static margin, parasite-drag build-up, polar, stall/min-power/min-drag speeds, electric endurance/range, climb, static thrust-to-weight and spar root stress, with pass/fail checks.
- `drone_mass_cg_budget`: Mass, CG and inertia budget from a listed bill of masses (point masses / solid boxes / supplied inertia tensors).
- `drone_propulsion_estimate`: HEURISTIC multirotor hover sizing: thrust per rotor, hover power/current, flight time, TWR, ESC and C-rate.
- `drone_regulatory_weight_class`: Coarse FAA/EASA weight-band, registration and Remote ID notes for a takeoff mass. NOT legal advice.
- `drone_rf_antenna_layout_check`: HEURISTIC antenna-layout check for vehicle trackers and small RF nodes: monopole orientation vs 'up', electrical length vs a quarter wave at the lowest band, cellular main/diversity spacing in wavelengths, GNSS patch sky view and clearance from cellular elements. Geometry rules only, not RF performance.

## enclosure_*

- `enclosure_button_stack`: Size a printed button cap over a tactile switch (D-pad, A/B, start/select): cap length from board, switch height, wall and protrusion, and check preload, flange clearance at full press and click-before-bottom-out.
- `enclosure_fit_check`: Packaging check for modules in an enclosure cavity: per-side clearance, pairwise separation, battery swelling allowance, antenna keep-outs vs metal parts, and wall thickness. Axis-aligned boxes; run a solid interference check too.
- `enclosure_module_catalog`: Off-the-shelf module envelopes (mm) with source and confidence. Catalog values are planning data; measure parts before cutting tools.
- `enclosure_oring_gland`: Check a static face-seal O-ring gland for a sealed / waterproof enclosure: squeeze (15-30 %), gland fill (<= 85 %), groove width, installed stretch and clamp-screw pitch vs flange thickness. Geometry rules; test the real seal.

## freecad_*

- `freecad_add_sketch_circle`: Add a circle to the active sketch
- `freecad_add_sketch_rectangle`: Add a rectangle to the active sketch
- `freecad_chamfer`: Add chamfer (angled cut) to edges
- `freecad_close_sketch`: Close/finalize a sketch
- `freecad_connect_to_freecad`: Connect to a running FreeCAD instance with NiRuLink FreeCAD addon
- `freecad_create_body`: Create a new PartDesign Body for parametric modeling
- `freecad_create_sketch`: Create a new sketch on a plane
- `freecad_execute_python`: Execute Python code in FreeCAD. Has full access to FreeCAD API including FreeCAD (App), FreeCADGui (Gui), Part, PartDesign, Sketcher, Draft, Mesh, and all other modules.
- `freecad_export_step`: Export model to STEP format
- `freecad_export_stl`: Export model to STL format for 3D printing
- `freecad_fillet`: Add fillet (rounded edge) to edges
- `freecad_get_objects`: List all objects in the active document
- `freecad_get_shape_info`: Get information about a shape (volume, area, bounding box)
- `freecad_new_document`: Create a new FreeCAD document
- `freecad_pad`: Extrude a sketch to create a 3D solid (add material)
- `freecad_pocket`: Cut into a solid using a sketch (remove material)

## kicad_*

- `kicad_analyze`: Read-only analysis of schematics and projects.
- `kicad_analyze_placement_telemetry`: Read telemetry data for calibration and convergence analysis.
- `kicad_audit`: Audit domain router — placement, clearance, and constraint verification.
- `kicad_autoroute`: PCB autorouting via FreeRouter (Specctra DSN/SES pipeline).
- `kicad_build_pcb_from_schematic`: Thin wrapper: derive pcb_path the same way the impl does, hold the write-lock for the whole pipeline (it creates AND mutates pcb_path through many steps), then delegate. See _build_pcb_from_schematic_impl for the real docstring/behavior.
- `kicad_design`: Firmware-spec front end: firmware -> design-intent -> partial schematic.
- `kicad_drc`: Design Rule Check operations for KiCad PCB files.
- `kicad_estimate_board_size`: Estimate minimum board dimensions from a list of footprints.
- `kicad_export`: Manufacturing and output-file exports.
- `kicad_get_usage_guidance`: Query onboarding knowledge: known issues, best practices, workflow.
- `kicad_lcsc`: Search, resolve, and assign LCSC/JLCPCB components.
- `kicad_library`: Symbol/footprint library operations.
- `kicad_panelize_pcb`: Panelize a PCB into a manufacturing panel using KiKit.
- `kicad_pcb`: PCB domain router — board lifecycle, footprints, nets, routing, zones, silkscreen.
- `kicad_project`: KiCad project management operations.
- `kicad_schematic`: Schematic domain router — file lifecycle, components, wires, labels, sheets.
- `kicad_schematic_layout`: Topology-aware automatic placement of schematic components.
- `kicad_suggest_placement`: Suggest component positions based on net connectivity.

## miniature_*

- `miniature_base_and_peg`: Base footprint (standard round/oval sizes), magnet pocket size and floor, and a keyed (D-flat) peg and socket for multi-part kits with per-side clearance for the process and fit (press/glue/slip). HEURISTIC clearances: print a tolerance coupon first.
- `miniature_base_catalog`: Round, oval, hex, square and rectangular bases plus scenic-top advice; smallest bases that fit a footprint.
- `miniature_detail_advice`: Scale-aware detail exaggeration: true size at scale, heroic multiplier, process limit and the size to model.
- `miniature_floor_clearance_check`: Building clearances: storey height and doors vs a figure on its base, drop-in floor fit, lip engagement, hatch.
- `miniature_hollow_plan`: Resin hollowing advice: hollow or not, shell thickness, resin saved, and drain + vent hole positions.
- `miniature_plate_pack`: Parts per build plate and plates per batch for a named printer (shelf packing of print-pose footprints).
- `miniature_printability_check`: HEURISTIC printability screen of one miniature part for MSLA resin or 0.2 mm-nozzle FDM: watertight/manifold, separate bodies, enclosed voids (need drain + vent), wall thickness by ray casting (resin: supported 0.4 / unsupported 0.6 mm), thin spikes vs the Formlabs wire table, overhang area by angle, islands, suction cups sealed by the vat film, volume and resin mass, build-volume fit. Each check carries its basis; confirm in a slicer.
- `miniature_scale_convert`: Convert real sizes to model sizes (or back) for a named scale and flag features below the process limits (walls, wires, holes, embossed/engraved detail, gaps) with the exaggeration needed to print them. Figure scales (28/32 mm heroic) become 1:N by eye or crown height. HEURISTIC; resin limits from the Formlabs Design Guide.
- `miniature_split_plan`: Cut plan for a part too big for a named printer, with peg size, count, keying and clearance per joint.
- `miniature_support_plan`: HEURISTIC print-orientation screen: samples rotations about x and y and ranks them by the largest layer area (MSLA peel and suction force), support area (faces flatter than the self-supporting angle) and support-start points (local minima). Returns rotate_deg for miniature_printability_check. Does not place supports.
- `miniature_terrain_grid_check`: Snap a terrain footprint to a gaming grid and lay out edge connectors (magnets or OpenLOCK-style clips) with checks.

## pcb_*

- `pcb_add_schematic_label`: Add a net label to the schematic. Labels define net names for wires. Coordinates in mils. Place on wire endpoints or pin positions.
- `pcb_add_schematic_symbol`: Add a symbol (component) to the schematic using s-expression format. This is an advanced tool that requires knowledge of KiCad's s-expression format.
- `pcb_annotate_symbols`: Auto-annotate all symbols with reference designators (R1, R2, C1, etc.).
- `pcb_begin_commit`: Begin a transaction for multiple changes. Changes won't appear until end_commit is called.
- `pcb_check_clearance`: Check if a point or track segment would violate clearance rules against existing copper. Use before placing tracks to validate paths.
- `pcb_connect_to_kicad`: Connect to a running KiCad instance. You must call this first before using other tools.
- `pcb_delete_item`: Delete a track or via by its ID
- `pcb_delete_schematic_item`: Delete a schematic item (wire, label, symbol, etc.) by its ID
- `pcb_draw_schematic_wire`: Draw a wire segment between two points in the schematic. Coordinates in mils. Use position_mils from get_symbol_pins to connect to exact pin locations.
- `pcb_end_commit`: End a transaction, either committing or dropping all changes since begin_commit
- `pcb_find_path`: Find a collision-free path between two points using A* pathfinding. Returns waypoints that can be used with place_track.
- `pcb_get_design_rules`: Get design rules (clearances, track widths, via sizes) for all net classes. Essential for knowing valid routing parameters.
- `pcb_get_kicad_version`: Get the version of the connected KiCad instance
- `pcb_get_layers`: Get information about enabled board layers
- `pcb_get_nets`: Get all nets (electrical connections) defined on the board
- `pcb_get_obstacles`: Get all obstacles on a layer that would block routing. Useful for understanding what's in the way.
- `pcb_get_pads`: Get all pads (footprint pins) on the board. Essential for routing as it provides pad positions and their net assignments.
- `pcb_get_ratsnest`: Get the ratsnest (unrouted connections) showing which pads need to be connected. Returns nets with 2+ pads, their connection requirements, and routing status.
- `pcb_get_schematic_junctions`: Get all wire junctions in the schematic. Junctions indicate where wires connect.
- `pcb_get_schematic_labels`: Get all labels in the schematic. Labels define net names and connections between wires.
- `pcb_get_schematic_no_connects`: Get all no-connect symbols in the schematic. No-connects indicate intentionally unconnected pins.
- `pcb_get_schematic_sheets`: Get all hierarchical sheets in the schematic. Sheets allow multi-page designs.
- `pcb_get_schematic_symbols`: Get all symbols (components) in the schematic. Returns component references, values, positions (in mils), and library IDs. Use position_mils to get coordinates for wiring.
- `pcb_get_schematic_wires`: Get all wire segments in the schematic. Wires connect component pins and labels.
- `pcb_get_symbol_libraries`: Get all available symbol libraries. Returns library names, descriptions, and symbol counts. Use this to discover what libraries are available before searching for symbols.
- `pcb_get_symbol_pins`: Get all pins of a specific symbol in the schematic. Returns pin names, numbers, positions in mils (position_mils), electrical types, and net connections. Use these mil coordinates directly with draw_schematic_wire to connect pins. Use get_schematic_symbols first to get the symbol ID.
- `pcb_get_tracks`: Get existing tracks on the board
- `pcb_get_vias`: Get existing vias on the board
- `pcb_place_symbol`: Place a symbol from a library onto the schematic. Use search_symbols first to find the library and symbol name. Coordinates are in mils (1 mil = 0.0254mm). A4 page is ~11700 x 8300 mils. Center of page is roughly (5850, 4150).
- `pcb_place_track`: Place a track segment between two points. Returns the track ID if successful.
- `pcb_place_via`: Place a via at a specific location to connect between layers
- `pcb_route_pads`: Route between two pads using KiCad's Push & Shove router. This is the RECOMMENDED way to route - it automatically avoids obstacles, pushes existing tracks, and maintains DRC clearances.
- `pcb_search_symbols`: Search for symbols across all libraries by name or keyword. Use this to find the right library and symbol name before placing. Example queries: 'resistor', 'op amp', 'MOSFET', 'connector'.
- `pcb_suggest_route`: Suggest a route between two pads by pad reference (e.g., 'R1-1' to 'C1-2'). Automatically finds pad positions and calculates path.
- `pcb_update_symbol`: Update a symbol's position, rotation, or field values (Reference, Value, etc.).

## unified_*

- `unified_get_context`: Report routing, startup availability and explicit project/units boundaries; not design approval.
